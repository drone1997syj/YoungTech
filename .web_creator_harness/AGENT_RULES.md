## 2. 이 프로젝트의 특수 제약

### 2.1 `server/index.js` 단일 파일 구조

- 약 4,220줄, 15만 바이트. 백엔드 전체가 한 파일에 있다.
- **파일 전체는 컨텍스트 한도(10만 자)를 초과해 통째로 넣을 수 없다.**
- **구간 추출을 사용한다**: `server/index.js::함수명` 또는 `server/index.js::/api/경로`
  ```
  server/index.js::sanitizeUser
  server/index.js::createTemporaryPassword
  server/index.js::/api/orders
  ```
- 구간 추출하면 해당 함수/라우트만 잘려 나온다 (예: `/api/orders` = 약 5,800자)
- 전체를 읽어야 할 때는 `search_files`로 위치를 찾은 뒤 해당 구간만 읽는다.
- 수정 시 같은 이름의 함수가 이미 있는지 반드시 확인한다.

### 2.2 DB 자동 마이그레이션 위험

- `server/db.js`의 `initDb()`는 **서버 기동 시 자동으로 ALTER/CREATE를 실행**한다.
- 따라서 `db.js` 수정은 곧 **운영 DB 스키마 변경**이다.
- 운영 DB에 영향을 주는 변경은 **반드시 사전 승인**을 받는다.
- 로컬에서 먼저 검증하고, 운영 적용은 별도 단계로 분리한다.

### 2.3 worktree 구조

- `YoungTech_deploy` / `orderfix` / `orderfix2` 는 독립 폴더가 아니라 **git worktree**다.
- 각 폴더의 `.git`은 파일이며 `gitdir:` 경로가 하드코딩되어 있다.
- **폴더명을 변경하면 git이 깨진다.**
- 작업은 `YoungTech`(main)에서 하고, worktree는 참고·비교용으로만 쓴다.

### 2.4 `.env` 취급

- `.env`에는 DB 비밀번호, JWT 시크릿, OAuth 키, SMTP 비밀번호가 들어 있다.
- **값을 읽거나 출력하지 않는다.** 변수명과 설정 여부만 확인한다.
- AI 컨텍스트에 `.env`를 절대 포함하지 않는다.
- `.env.example`만 참고한다.

## 3. 파일 수정 규칙

1. 수정 전 대상 파일과 관련 코드를 확인한다.
2. **파일 수정은 HermesPCController(JSON Action) 또는 UWCH 패치 적용으로만** 수행한다.
   - 셸 `cat`/`sed`/`echo`로 파일을 직접 고치지 않는다.
3. UWCH 패치를 쓸 경우 아래 형식을 정확히 지킨다.
4. SEARCH 문자열은 대상 파일에서 **정확히 한 번** 일치해야 한다.
   - 0회 또는 2회 이상이면 임의 수정하지 말고 원인을 확인한다.
5. 비밀정보 파일과 운영 설정을 컨텍스트에 포함하지 않는다.
6. 사용자 승인 없이 삭제·초기화·운영 데이터 변경을 하지 않는다.
7. 수정 후 **반드시 되읽어 검증**한다.

### 3.1 UWCH 패치 형식

```text
### FILE: server/index.js
<<<<<<< SEARCH
대상 파일에서 정확히 한 번 나타나는 기존 코드
=======
교체할 새 코드
>>>>>>> REPLACE
```

- 파일이 여러 개면 `### FILE:` 블록을 이어서 작성한다.
- 패치 블록 외의 설명문을 같은 입력란에 섞지 않는다.
- SEARCH/REPLACE는 원본과 **공백·들여쓰기까지 정확히** 일치시킨다.

## 4. 이 프로젝트에서 반드시 지킬 검증

쇼핑몰은 **돈과 재고와 개인정보**를 다룬다. 다음은 낮은 위험이 아니다.

| 변경 대상 | 요구 검증 수준 |
|---|---|
| 주문 생성·금액 계산 | 서버측 검증 필수. 클라이언트 금액을 신뢰하지 않는다 |
| 재고 차감 | 트랜잭션 + 동시성 확인 |
| 결제·환불 | 실제 실행 전 승인. 모의/실제 구분 명시 |
| 인증·권한 | E2E 수준 확인 |
| DB 스키마 | 로컬 검증 → 승인 → 운영 |
| 상품 표시·CSS | 문법 검사 수준 |

### 4.1 절대 하지 말 것

- 클라이언트가 보낸 `price`, `total_amount`를 서버에서 그대로 저장
- 재고 확인 없이 주문 확정
- 인증 없이 관리자 API 노출
- `.env` 값을 코드에 하드코딩

## 5. 보안 및 운영

- API 키, 비밀번호, 토큰, 개인정보를 코드·로그·AI 컨텍스트에 노출하지 않는다.
- 운영 배포, 도메인/DNS 변경, 유료 결제, DB 데이터 변경은 **사전 승인**을 받는다.
- DB 백업 생성과 실제 복구 검증을 구분한다.
- 보안 설정을 임의로 완화하지 않는다.

```text

- 수정·생성한 파일

- 실행한 테스트
- 결과: PASS / FAIL / BLOCKED / NOT RUN

## 배포 및 운영 상태
- 호스팅 / 도메인 / DB / 백업 — 확인한 것만, 못한 것은 "미확인"

## 사용자 조치
- 승인·직접 작업이 필요한 항목

## 남은 문제와 다음 작업
```

### 상태 표기 7단계

`Implemented` | `Verified` | `Deployed` | `Connected` | `Operational` | `User Action Required` | `Blocked`

**코드 작성만 끝난 상태를 배포·연동 완료라고 쓰지 않는다.**

## 8. 하네스 한계 인식

- UWCH는 AI와 자동 연결된 도구가 **아니다.** 사용자가 컨텍스트와 패치를 직접 전달한다.
- 하네스에서 검증·적용 확인 전에는 "파일 수정 완료"라고 보고하지 않는다.
- 하네스가 하지 않는 것: AI 직접 호출, MCP 연결, 자동 배포, DNS/SSL 변경, 운영 DB 변경, Git 자동 commit/reset/clean
